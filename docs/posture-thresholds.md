# 자세 판정 임계값

판정은 **온보딩에서 잡은 개인 기준값(baseline) 대비 상대값**으로 한다.
절대 각도를 쓰지 않는 이유: 사람마다, 모니터 높이마다 평소 각도가 다르다.

## 구현 위치

판정 로직은 AI 파트 레포(`kayo2e/pyeobugi-AI`)의 코어를 그대로 가져온 것이다.
**`src/shared/ai/` 안의 파일은 여기서 고치지 않는다.** 고쳐야 하면 AI 레포에 반영한 뒤 다시 가져온다.

| 파일 | 역할 |
| --- | --- |
| `src/shared/ai/score.ts` | 점수 계산(`postureScore`), 진입·복귀 기준선, severity 구간 |
| `src/shared/ai/engine.ts` | 상태 기계(`stepEngine`), 시간 상수, 추론 주기, EMA 평활 |
| `src/shared/ai/feedback.ts` | 화면에 쓰는 단계(`UNCALIBRATED`/`GOOD`/`PENDING_BAD`/`BAD`/`RECOVERING`) |
| `src/shared/ai/distance.ts` | 얼굴 크기 변화로 "기준 다시 잡기" 안내 |
| `src/shared/ai/face-geometry.ts` | BlazeFace 키포인트 6개에서 pitch 근사 |
| `src/shared/sensitivity.ts` | **우리 코드.** 교정 강도 3단계를 기준값 이동으로 구현 |

## 점수

pitch 편차와 얼굴 크기 변화를 하나의 점수로 합친다 (`postureScore`).

| 상수 | 값 | 뜻 |
| --- | --- | --- |
| `PITCH_DEADZONE` | 1.5° | 이만큼은 흔들림으로 보고 센다 |
| `PITCH_WEIGHT` | 1.4 | 1도당 점수 |
| `SIZE_GATE_START` / `SPAN` | 6° / 5° | 얼굴 크기는 **머리를 숙인 뒤에야** 점수에 들어간다 |
| `SIZE_WEIGHT` | 120 | 크기 변화 1당 점수 |
| `SCORE_DEADZONE` | 4 | 합계가 이 아래면 0 |
| `BAD_ENTER_SCORE` | 3 | 이 점수를 넘으면 나쁜 자세 후보 |
| `BAD_EXIT_SCORE` | 2 | 이 아래로 내려와야 복귀 |

얼굴 크기에 게이트를 둔 이유: 화면 쪽으로 몸만 기울여도 얼굴이 커지기 때문에,
고개가 실제로 숙여진 뒤에만 크기를 반영한다.

severity 는 점수로 매긴다 — `18` 이상 SEVERE, `10` 이상 MODERATE, 나머지 MILD.
확정될 때까지 **가장 심했던 정도**를 쓴다(`maxSeverity`).

## 시간

`TIMING` (`engine.ts`)

| 이름 | 값 | 뜻 |
| --- | --- | --- |
| `enterAfterMs` | 3초 | 이 시간 이어져야 나쁜 자세로 **확정** |
| `exitAfterMs` | 2초 | 이 시간 바른 자세여야 **복귀** |
| `lostAfterMs` | 3초 | 얼굴을 이만큼 못 보면 자리비움 |
| `idleIntervalMs` | 1초 | 평소 추론 주기 |
| `pendingIntervalMs` | 0.25초 | 자세가 바뀌는 중에는 촘촘하게 |
| `awayIntervalMs` | 3초 | 자리비움 1분 뒤부터 느리게 |

pitch·size 는 `SMOOTHING_TIME_MS = 1초` 의 시간 기반 EMA 로 평활한다 (프레임이 빠져도 같은 결과).

## 교정 강도 (우리 구현)

AI 엔진은 진입·복귀 점수가 고정이라 밖에서 바꿀 수 없다.
대신 **엔진에 넣는 기준 pitch 를 옮겨** "몇 도부터 걸리는지" 를 바꾼다 (`tunedBaseline`).
저장된 기준값 자체는 그대로 둔다 — 재설정·거리 안내가 그 값을 쓴다.

| | 0 느슨하게 | 1 보통 (기본) | 2 엄격하게 |
| --- | --- | --- | --- |
| 나쁜 자세로 보는 각도 | 기준 +15° | 기준 +10° | 엔진 기본값(약 +6.5°) |

> TODO(AI 팀): 진입·복귀 점수를 옵션으로 받을 수 있으면 이 우회가 필요 없다.

## 거리 안내

`DISTANCE` (`distance.ts`) — 얼굴 크기가 기준보다 `25%` 이상 달라진 상태가 `8초` 이어지면
"기준을 다시 잡아 주세요" 말풍선을 띄운다. `15%` 안으로 돌아오면 해제한다.

## 판정 규칙

- 기준을 벗어난 상태가 3초 이어져야 나쁜 자세로 확정한다.
- 확정되는 그 순간에만 `POSTURE_BAD` 를 **한 번** 보낸다. 계속 숙이고 있어도 늘지 않는다.
- `occurredAt` 은 판정 시각이 아니라 **나쁜 자세가 시작된 시각**이다(엔진이 소급해 준다).
- 복귀는 `BAD_EXIT_SCORE` 아래로 내려온 상태가 2초 이어져야 인정한다.
  진입선보다 낮게 둬서 기준선 근처에서 상태가 깜빡이지 않는다.
- 복귀한 뒤 다시 나빠지면 또 한 번 보낸다. 복귀 전에 잠깐 폈다 다시 숙이는 것은 세지 않는다.
- **얼굴이 보이지 않는 동안은 판정을 멈춘다.** 자리 비움이 나쁜 자세로 쌓이지 않고,
  돌아오면 처음부터 다시 잰다.
- 나쁜 자세 **시간**은 `phase === 'BAD'` 인 동안만 센다. `RECOVERING` 에서 세면
  소급된 전이와 중복된다.

## 알려진 한계 (AI 레포 측정, 1인 60초 × 6개 라벨)

| 자세 | 나쁜 자세로 판정된 비율 |
| --- | --- |
| 바른 자세 | 4.2% |
| 거북목(머리 내밀기) | 77.5% |
| 고개 숙임 | 95.0% |

- 바른 자세 오탐은 **기준을 다시 잡지 않고 10~20cm 뒤로 앉은** 기록에서만 발생했다.
  앉는 거리가 바뀌면 각도 기준이 약 5도 이동한다 → 거리 안내와 "기준 다시 잡기" 가 중요하다.
- 거북목·고개 숙임이 100%가 아닌 것은 3초 대기와 평활 때문이다 (의도한 동작).
- 필기처럼 정상적인 짧은 숙임도 3초를 넘으면 알림이 간다. 유지 시간을 늘릴지는
  AI 레포의 숙임 구간 길이 분포(중앙값·p90) 분석 결과를 보고 정한다.
- 거북목과 고개 숙임은 구분하지 않고 하나의 "나쁜 자세" 로 본다 (AI 레포 ADR 0002).

## 검출기

MediaPipe **Face Detector(BlazeFace short-range, 0.23MB)** 로 키포인트 6개를 얻고,
`face-geometry.ts` 에서 pitch 를 근사한다. CPU delegate, 추론 해상도는 320px 고정이라
온보딩 프리뷰 해상도를 올려도 추론 비용은 그대로다.

## 서버로 가는 것

`POSTURE_BAD` 이벤트의 `severity` 뿐이다.
영상, 얼굴 이미지, 키포인트, pitch, 얼굴 크기, 개인 기준값, 슬라이더 값은 기기 밖으로 나가지 않는다.
온보딩 프리뷰 프레임도 렌더러 간 IPC 로만 오가고 저장하거나 로그에 남기지 않는다.

MediaPipe 는 실행할 때 구글(`odml.pa.googleapis.com`)로 사용 기록을 보내려 한다.
영상이 아니라 사용 통계지만, detector 페이지의 CSP(`default-src 'self'`)가 이를 막는다.
끄는 설정이 없어서 CSP 로 막고, 콘솔 소음만 `windows.ts` 에서 걸러낸다.
